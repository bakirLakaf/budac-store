# متجر BUDAC — دليل التشغيل

## 1. التثبيت

```bash
pip install -r requirements.txt
cp .env.example .env
```

افتح `.env` وبدّل `SECRET_KEY` بسلسلة عشوائية طويلة. باش تولّد وحدة:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

## 2. تجهيز قاعدة البيانات

بالترتيب:

```bash
python seed_shipping.py     # 58 ولاية × 3 شركات توصيل
python create_admin.py      # حساب لوحة التحكم (كلمة السر مخفية أثناء الكتابة)
python import_from_youcan.py  # سحب المنتجات من متجر YouCan (اختياري)
```

بدل `import_from_youcan.py` تقدر تستعمل `python seed.py` لمنتجات تجريبية.

## 3. التشغيل

```bash
python app.py
```

- المتجر: http://127.0.0.1:5000
- لوحة التحكم: http://127.0.0.1:5000/admin/login

## نقاط مهمة تعرفها

### الفرق بين "فارغ" و"صفر" فأسعار التوصيل
- **خانة فارغة** = الشركة ما توصلش لهاد الولاية → الزبون يشوف "غير متوفر"
- **صفر** = توصيل مجاني

هاد الفرق مبني فالكود عمدًا. مثال حقيقي: **برج باجي مختار** ما تخدمهاش ZR ولا World — غير Yalidine.

### الوصف بالـHTML
كي تكتب وصف فيه وسوم HTML (أو يجي من YouCan)، النظام يخزّن نسختين:
- `description_html` — الأصل كما هو
- `description` — نص واضح مقروء (هو اللي يبان فالمتجر)

### الـslug بالعربية
`slugify` تخلي الحروف العربية كما هي (مثلاً `أشرطة-المرايا`). هذا صحيح ويخدم فكل المتصفحات الحديثة. إذا حبيت روابط لاتينية، اكتب الـslug يدويًا فلوحة التحكم.

### حماية من الحذف الخاطئ
- ما تقدرش تمسح منتج داخل فعرض شغال
- ما تقدرش تمسح تصنيف فيه منتجات

الرسالة توضح السبب والحل.

## رحلة الشراء

```
منتج → السلة → كوبون (اختياري) → checkout → تأكيد → تتبّع
```

- **السلة** فالـsession. نخزّنو غير المعرّفات والكميات — الأسعار تتجاب من قاعدة
  البيانات فكل مرة، باش حد ما يقدرش يعدّل الكوكي ويبدّل السعر.
- **التوصيل** يتحسب فالسيرفر، ماشي من الفورم. الصفحة تعرضو مباشرة عبر
  `/api/shipping-price`، لكن السيرفر يعاود يحسبو قبل التسجيل.
- **المخزون** ينخصم وقت الطلب (ماشي التسليم)، ويرجع تلقائيًا إذا لغيت الطلبية.

### أنواع الكوبونات
| النوع | مثال |
|---|---|
| نسبة مئوية | 10% مع سقف اختياري |
| مبلغ ثابت | 500 دج |
| توصيل مجاني | يلغي سعر التوصيل |

كل نوع يقبل: حد أدنى للطلبية، عدد استعمالات، وتواريخ بداية/نهاية.

### تتبع الطلبية
الزبون يحتاج **رقم الطلبية + رقم الهاتف** معًا. هذا عمدي — بلا الهاتف، أي واحد
يقدر يجرّب أرقام ويشوف طلبيات الناس.

## ملاحظات أمنية

### CSRF
كل فورم فيه `{{ csrf_token() }}` تلقائيًا. إذا زدت فورم POST جديد، **لا تنسى التوكن**:

```html
<form method="post">
    <input type="hidden" name="csrf_token" value="{{ csrf_token() }}">
    ...
</form>
```

بلاه الفورم يرجع خطأ 400.

### الكوكي فالإنتاج
`SESSION_COOKIE_SECURE` تجي من `.env` وقيمتها الافتراضية `false` (باش التطوير المحلي يخدم).
**كي تنشر الموقع على https، حطها `true`:**

```
SESSION_COOKIE_SECURE=true
```

### حد الرفع
`MAX_CONTENT_LENGTH = 6MB` — Flask يرفض أي طلب أكبر قبل ما يقراه للذاكرة.

## قيود معروفة (بصراحة)

**1. سباق على آخر قطعة (race condition)**
إذا زبونين طلبو آخر قطعة **فنفس اللحظة بالضبط**، ممكن الاثنين ينجحو. SQLite ما عندهاش
قفل صف (row locking) قوي. الحل الحقيقي هو الانتقال لـPostgreSQL مع `SELECT FOR UPDATE`.
عمليًا الاحتمال ضعيف بزاف فمتجر بحجم متوسط، لكن لازمك تعرف بيه.

**2. نفس الشي للكوبونات**
`usage_limit` يقدر يتجاوز بواحد أو اثنين فحالة استعمال متزامن.

**3. إرجاع المخزون للمنتجات ذات التنويعات**
كي تلغي طلبية باقة، الكمية ترجع **للتنويعة الافتراضية** ماشي للتنويعات اللي انخصمو منها
بالضبط. المجموع يبقى صحيح (وهو المهم محاسبيًا)، لكن التوزيع بين التنويعات ممكن يتبدّل.

## تحسين الصور (WebP) — تلقائي

الموقع يحوّل **كل** صورة لـWebP تلقائيًا، ما تحتاجش أدوات خارجية.

### واش يصرا لكل صورة ترفعها

| | الأصل | بعد المعالجة |
|---|---|---|
| صورة هاتف 3024×4032 | 1.4 ميغا | **71 كيلو** (نسخة رئيسية 1200px) |
| | | **20 كيلو** (مصغّرة 450px) |

**ليش نسختين؟** بطاقة المنتج فالشبكة تعرض الصورة بـ~250 بكسل. تحميل نسخة 1200 بكسل
باش تعرضها فـ250 هو هدر خالص. صفحة فيها 12 منتج:
**16 ميغا → 235 كيلو**.

هذا يخدم تلقائيًا فـ:
- رفع الصور من **لوحة التحكم**
- سحب الصور من **YouCan** (`import_from_youcan.py`)

### ⚠️ شكل بيانات YouCan (مهم)

فحصنا البيانات الحقيقية من متجرك، ولقينا حاجتين مختلفتين عن التوقعات:

**1. التنويعات فـ`variant_options` ماشي `variants`**

الرد يجي هكذا:
```json
"variant_options": [
  {"name": "اللون", "type": 2, "values": ["دوري", "أرجونتي"]}
]
```

يعني عندنا **أسماء التنويعات فقط** — بلا أسعار ولا مخزون فردي (هاديك تحتاج
API خاص بمفتاح المتجر). فكل تنويعة ترث سعر المنتج الأساسي.

إذا منتج عندو **خيارين** (مثلاً "العرض" × "اللون")، نولّدو كل التركيبات:
`1.5 سم / دوري`، `1.5 سم / أرجونتي`... كيما يصرا فعليًا عند YouCan.

**2. التصنيفات ما تجيش مع المنتج**

رد `/api/products/<slug>` ما فيهش حقل للتصنيفات. الحل: نجيبوهم بالعكس عبر
`/api/categories?include=products` — مسار عمومي **ما يحتاجش توكن**.

### 🔑 توكن Admin API (اختياري لكن مفيد)

بلا توكن، الاستيراد يخدم لكن التنويعات **ترث سعر المنتج الأساسي** (لأن الأسعار
الفردية ما تجيش فالمسار العمومي).

**بالتوكن**، تجيك:
- التصنيفات مباشرة مع كل منتج
- **التنويعات بأسعارها ومخزونها وSKU وصورها**

احصل عليه من: لوحة تحكم YouCan ← الإعدادات ← API، وحطو فـ`.env`:

```
YOUCAN_ACCESS_TOKEN=xxxxx
```

الصلاحيات المطلوبة: `read-products` و`read-categories`.

⚠️ **التوكن سري** — ملف `.env` ما يترفعش لـGit أبدًا (موجود فـ.gitignore).
إذا التوكن غلط أو منتهي، السكريبت يقولك ويكمّل بالمسار العمومي بدل ما يفشل.

### كيفاش يقرر السكريبت

```
عندك توكن؟ → Admin API (أغنى بيانات)
     ↓ لا
/api/categories?include=products  → للتصنيفات
/api/products/<slug>              → للصور والتنويعات (أسماء فقط)
```

### تشخيص الاستيراد

كي تشغّل `import_from_youcan.py`، يتولّدو ملفان:

| الملف | واش فيه |
|---|---|
| `debug_report.txt` | **ابدا بيه** — تقرير مقروء: كل منتج وواش لقينا فيه |
| `debug_all_products.json` | البيانات الخام لكل المنتجات |

التقرير يوريك:
- **كل منتج على حدة**: صور، تنويعات، تصنيف، والمشاكل فيه
- **تحليل الأنماط**: كم منتج بلا تصنيف، كم بلا صور
- **المفاتيح الموجودة** فبيانات YouCan وفكم منتج — هذا يكشف بالضبط إذا كان
  اسم الحقل مختلف عن المتوقع

⚠️ **ليش كل المنتجات ماشي الأول فقط؟** لأن المشاكل عادة ما تكونش موحّدة:
منتج عندو تنويعات ومنتج لا، منتج عندو تصنيف ومنتج لا. بفحص الأول وحدو،
تقدر تستنتج غلط أن "كلشي مليح" ولا "كلشي خايب".

إذا لقيت مشكل، ابعثلي **`debug_report.txt`**.

### تحويل الصور القديمة

إذا عندك صور قديمة (JPG/PNG) مستوردة من قبل:

```bash
python optimize_images.py            # معاينة — ما تبدّل والو
python optimize_images.py --apply    # التحويل الفعلي
```

**دائمًا شغّل المعاينة أولاً.** السكريبت يبدّل ملفات **ويحدّث قاعدة البيانات**،
فأحسن تشوف واش راح يصرا قبل.

الصور الأصلية تتنقل لـ`static/img/_originals_backup/` — **ما تتمسحش**.
شوف الموقع، وإذا كلشي مليح تقدر تمسح هاد المجلد.

تقدر تشغّلو أكثر من مرة بأمان — الصور المحوّلة من قبل يتخطاها.

### تفاصيل تقنية

- **الأبعاد القصوى**: 1200×1200 (رئيسية)، 450×450 (مصغّرة)
- **الجودة**: 82 للرئيسية، 78 للمصغّرة — نقطة التوازن وين العين ما تفرّقش
- **دوران الصور**: يتصحّح تلقائيًا من بيانات EXIF. صور الهاتف كثير تجي مقلوبة، وبلا هاد التصحيح تبان مقلوبة فالموقع رغم أنها صحيحة فالهاتف.
- **الشفافية**: محفوظة (مهمة للوغوهات وPNG)

### هل WebP مدعوم؟

فوق **97%** من المتصفحات عالميًا: Chrome، Firefox، Safari 14+، Edge، وكل متصفحات
الأندرويد والآيفون الحديثة.

## المخزون: نظام مفتوح

الموقع **ما يتبّعش الكميات**. كل المنتجات متوفرة دائمًا.

**ليش؟** الكميات تتبدّل بسرعة فالمحل الحقيقي، وتتبّع غير دقيق أسوأ من بلا تتبّع:
يمنع بيعة موجودة فعلاً.

الحقول `stock_quantity` باقية فقاعدة البيانات (ما مسحناهمش) باش الطلبيات القديمة
تبقى صحيحة. إذا حبيت **ترجّع التتبّع** بعدين، بدّل سطر واحد فـ`models.py`:

```python
class Product(db.Model):
    is_stock_tracked = True    # كانت False
```

وكل المنطق يرجع يخدم — الحجز، الإرجاع عند الإلغاء، تنبيهات "نفذت الكمية".

### رقم الواتساب

يتضبط من `.env`:
```
WHATSAPP_NUMBER=213676672334
```
بصيغة دولية **بلا + وبلا مسافات**.

الرسالة تتغيّر حسب الصفحة: من صفحة منتج تجي *"عندي سؤال على هذا المنتج: [الرابط]"* —
فما تحتاجش الزبونة تشرح وين كانت.

### شفتها مؤخرًا

تتخزّن فمتصفح الزبون (`localStorage`)، ماشي عند السيرفر. آخر 8 منتجات.
ما تحتاجش حساب، وما تكبّرش الكوكي.

### نسخ الروابط والأرقام

⚠️ `navigator.clipboard` يخدم غير على **https** أو localhost. محليًا على
`127.0.0.1` يخدم، لكن لو فتحت الموقع بـIP الجهاز فالشبكة (مثلاً `192.168.1.5`)
النسخ يستعمل الطريقة القديمة تلقائيًا. بعد النشر على https كلشي يخدم عادي.

## ميزات التسويق (مستوحاة من YouCan ومحسّنة)

### 🔴 السلات المتروكة — الأهم

**الفرق عن YouCan**: هما يبعثو إيميل تلقائي. فالجزائر الإيميل ضعيف — بزاف من
الزبائن ما عندهمش إيميل نشط، والرسائل تروح للسبام.

نحنا نسجّلو **رقم الهاتف** بمجرد ما الزبون يكتبو فالـcheckout (قبل ما يضغط
"أكّد")، والأدمن يشوفهم فـ**لوحة التحكم ← السلات المتروكة** مع:
- زر **واتساب** برسالة جاهزة معمّرة باسم الزبون ومنتجاتو
- الرقم قابل للاتصال مباشرة
- محتوى السلة وقيمتها

كي الزبون يكمّل الطلب، السلة تتعلّم **تلقائيًا** كـ"استُرجعت" — باش ما تتصلش
بواحد خلّص أصلاً.

### الاقتراحات (Upsell)

**الفرق عن YouCan**: هما يعرضو الاقتراح **بعد** الشراء. نحنا نعرضوه **فالسلة** —
الزبون مازال فوضع شراء، فاحتمال القبول أعلى، وما نخربوش عليه فرحة إتمام الطلب.

من **الاقتراحات** فلوحة التحكم:
- "كي يشري X، اقترح Y" — أو اقتراح عام لكل السلات
- خصم تحفيزي اختياري (5-15% يزيد القبول بشكل ملحوظ)

### تقييمات الزبائن

⚠️ كل تقييم يحتاج **موافقتك** قبل ما يبان. بلا هذا، أي واحد يقدر يكتب سبام
أو إساءة ويبان فورًا فمتجرك.

عدّاد التقييمات المنتظرة يبان فالقائمة الجانبية.

### بيكسل الإعلانات

فـ`.env`:
```
FACEBOOK_PIXEL_ID=123456789
TIKTOK_PIXEL_ID=ABCDEF
```

إذا خليتهم فارغين، **ما يتحمّل حتى سكريبت** — الموقع يبقى خفيف.

### SEO

- `/sitemap.xml` — خريطة تلقائية لكل صفحاتك
- `/robots.txt` — يمنع فهرسة لوحة التحكم والسلة
- **Open Graph** — الرابط يبان بصورة المنتج وسعرو كي يتشارك فواتساب وفيسبوك

## تفعيل/إلغاء شركات التوصيل

**أسعار التوصيل ← اختر الشركة ← زر تفعيل/تعطيل**

الشركة المعطّلة ما تبانش للزبون فالـcheckout، لكن **أسعارها وولاياتها تبقى محفوظة**.
إذا رجعت تخدم معاك، تفعّلها بنقرة وتلقى كلشي كيما كان.

⚠️ ما تقدرش تعطّل **آخر شركة نشطة** — بلاها ما يقدر حتى زبون يكمّل طلبية.

## حاسبات الكمية

للمنتجات اللي تتباع بالمتر. الزبون يعطي مقاس الحاجة، والموقع يحسبلو شحال يحتاج.
هذا يقلل التردد ("شحال ناخذ؟") ويزيد الطلبات.

### نوعان

**1. حاسبة المحيط** — للأشرطة اللي تدور حول حاجة (جوان ميروار، السفيفة، الكريستال)

الزبون يختار شكل المرآة: **دائرية** (القطر) / **مربعة** (الضلع) / **مستطيلة** (طول×عرض)،
ويحدد عدد القطع. النتيجة: الأمتار المطلوبة + **عدد اللفات**.

الإعداد: نوع الحاسبة = `محيط` + `طول اللفة` (مثلاً 5 م).

**2. حاسبة المساحة** — للورق اللاصق

الزبون يعطي أبعاد السطح (ويقدر يزيد **عدة أسطح**). النتيجة: الأمتار الطولية المطلوبة.

الإعداد: نوع الحاسبة = `مساحة` + `عرض اللفة` (1 أو 1.2 م).

⚠️ **الحساب ماشي مجرد «المساحة ÷ عرض اللفة»**. الورق يتقص بالطول من لفة عرضها
ثابت. إذا السطح أعرض من اللفة، نحتاجو عدة شرائط جنب بعض. الحاسبة تحسب هذا صح:
سطح 250 سم مع لفة 120 سم = **3 شرائط**.

### الإعداد
لوحة التحكم ← المنتجات ← تعديل ← **حاسبة الكمية**

**هامش الأمان** (10% افتراضيًا) يُزاد على الحساب للقص والأخطاء.

## ZR Express API

يخليك تبعث الطلبيات بنقرة، وتجيك أرقام التتبّع تلقائيًا.

### الربط

من حسابك عند ZR ← **Documentation API ← Jetons API**. تحتاج **قيمتين**:

```
ZR_TENANT_ID=xxxxx
ZR_API_KEY=xxxxx
```

بعدها: **لوحة التحكم ← التكاملات ← اختبر الاتصال** (جرّب قبل أول طلبية حقيقية).

### واش يخدم

| وين | واش |
|---|---|
| صفحة الطلبية | زر **«ابعث لـZR Express»** |
| بعد الإرسال | رقم التتبّع يتسجّل، والحالة ترقّى لـ«مؤكدة» |
| أي وقت | زر **«حدّث الحالة»** يجيب حالة الطرد من عندهم |

⚠️ **الفشل ما يكسرش الطلبية.** إذا ZR ما ردّش، الطلبية تبقى محفوظة والأدمن
يبعثها يدويًا أو يعاود يجرّب. ما نخسروش بيعة بسبب مشكل شبكة.

بلا المفاتيح، الموقع يخدم عادي — غير تبعث يدويًا كيما قبل.
