فنسخة، الزبون يلقى 4 طرود لطلبية وحدة.

### 3. بيكسل فيسبوك — منسوخ 3 مرات

كود التحميل كان مكرّر فـ`base.html` و`landing/page.html`
و`landing/thanks.html`.

**الخطر**: أي تبديل من فيسبوك لازم يتدار 3 مرات. وعطب فالبيكسل
**ما يبانش**: الصفحة تتفتح عادي، الزبون يشري عادي، وتكتشف المشكل
بعد أسبوعين كي تلقى أرقام الحملة غالطة وفلوس الإعلانات اتصرفت على
بيانات ناقصة.

ولّى ماكرو واحد فـ`templates/partials/fb_pixel.html`، وكل صفحة
تزيد أحداثها الخاصة برك:


## ⚠️ اقرا هذا أولاً

فـv128 زدنا زر «↑ لصور المنتج». الزر كان **شغّال**، بصح **ما بانش**.

### السبب

بطاقة الصورة التوضيحية عندها فالـCSS:

```css
.image-item { aspect-ratio: 1; overflow: hidden; }
```

مربّع ثابت يقصّ كل شي برّا الصورة. الزر كان داخلو → مقصوص.

### وحاجة أقدم بزاف

**خانة وصف الصورة التوضيحية كانت مخبّية من v124** — نفس السبب.
الحقل موجود فالقالب، والـCSS تاعو مكتوب، والجافاسكريبت اللي يحفظو
موجود. ما بان أبدًا.

يعني ميزة كاملة كانت مدفونة من زمان، ما اكتشفناهاش إلا كي طرحت
السؤال على الزر.

### الحل

المربّع المقصوص ولّى `.image-shot` **داخل** البطاقة، والوصف وزر
النقل **برّاه**:

```
┌─ .image-item (يكبر على قد المحتوى) ─┐
│  ┌─ .image-shot (مربّع مقصوص) ──┐  │
│  │   الصورة + أزرار ‹ 🔍 × ›     │  │
│  └───────────────────────────────┘  │
│  [ الموديل ▾ ] [ ↑ لصور المنتج ]   │
│  [ وصف قصير................... ]   │
└─────────────────────────────────────┘
```

والأزرار توّا تبان كي تمرّر على **الصورة** برك، ماشي على البطاقة
كاملة — وإلا كي تفتح قائمة الموديلات يطلعلك الغطاء الأسود.

### اختبار جديد يحرس هاد النوع من الأعطاب

اختبار «الصفحة ترجع 200» **ما يقبضش** زر مخبّي. زدنا فحوصات
على **بنية** البطاقة: الزر والوصف لازم يكونو برّا المربّع، والوسوم
متوازنة.

جرّبناه: حيّدنا `.image-shot` عمدًا، والاختبار طاح.

## نقل الصور بين المجموعتين

### المشكل

رفعت صورة موديل بالغلط فخانة «الصور التوضيحية»؟ ماكانش طريقة
تصلحها. أزرار `‹ ›` تحرّك الصورة **داخل مجموعتها برك** — مقصود،
باش صورة توضيحية ما تخربّطش ترتيب الموديلات.

الحل الوحيد كان: تمسحها وتعاود ترفعها.

### الحل

كل صورة توضيحية ولّى تحتها:

```
[ قائمة الموديلات ▾ ]  [ ↑ لصور المنتج ]
```

تختار الموديل من القائمة (ولا «بلا موديل») وتدوس. الصورة تنتقل
لصور المنتج وتتربط بالموديل مباشرة.

### واش يصرا تلقائيًا

| الحالة | التصرّف |
|---|---|
| نقل للصور الرئيسية | الوصف يتمسح (خاص بالتوضيحية برك) |
| نقل وأنت اخترت موديل | الموديل يتربط بالصورة فورًا |
| نقل والمنتج بلا صورة رئيسية | هي تولّي الرئيسية |
| نقل عكسي (رئيسية ⇐ توضيحية) | الموديل المربوط بيها **يتفكّ** |
| نقل الصورة الرئيسية تاع المنتج | صورة أخرى ترتقي مكانها تلقائيًا |

الحالة الأخيرة هي الأخطر: بلاها المنتج يبقى يشير لصورة برّا
المعرض، وصفحة المنتج تبان بصورة مكسورة.

### ⚠️ الاتجاه العكسي ماشي فالواجهة

زر «↓ للتوضيحية» ما زدناهش. علاه؟ معرض الصور الرئيسية يتدار
**فالمتصفح**، والقرارات (ترتيب، حذف، رئيسية) تتطبّق كي تدوس
«حفظ المنتج». زر يبعث للسيرفر دروك يعيد تحميل الصفحة و**يضيّع
تعديلاتك اللي ما حفظتهاش**.

المسار موجود فالسيرفر ومجرّب — نزيدو الزر إذا احتجتو.

### اختبار جديد

`tests/test_image_regroup.py` — **18 اختبار** يغطّيو الحالات
الخطيرة، بما فيها تفريغ كل صور المنتج (ما يطيّحش الصفحة).

## صفحة تتبّع الطلبية — ولّات مربوطة

الصفحة كانت **شغّالة بصح مخبّية**: ماكانش حتى رابط ليها فالموقع كامل.
الزبون ما يلقاهاش إلا إذا كتب `budacdz.com/track` بيدو.

زدنالها رابطين:

| وين | النص |
|---|---|
| الفوتر ← «خدمة الزبائن» | تتبّع طلبية |
| صفحة نجاح الطلبية | تتبّع الطلبية |

### علاه صفحة النجاح أهم من الفوتر

تمّة الزبون شايف رقم طلبيتو ونسخو دروك. هي اللحظة الوحيدة اللي
يكون فيها الرقم قدامو.

### وعلاه ما كفاتش «طلبياتي»

«طلبياتي» تقرا من **متصفح الزبون**. إذا مسح الكوكيز، ولا فتح من
هاتف آخر، ولا استعمل وضع التصفح الخفي — ما يلقى والو.
«تتبّع طلبية» تخدم برقم الطلبية + الهاتف، من أي جهاز.

هذا ينقّص أسئلة «وين وصلت طلبيتي؟» فالواتساب.
